# 手部形态检查 agent

可复用规则位于 [hand-anatomy-reviewer/SKILL.md](hand-anatomy-reviewer/SKILL.md)，已安装到本机 Codex 的个人 skills 目录。调用示例：

> 使用 $hand-anatomy-reviewer 检查这些手部图片。逐张、逐手追踪拇指、食指、中指、无名指、小指，检查数量、长度、关节连接、左右手和完整构图。输出缺陷位置、证据、修改建议和绑定原图的 JSON 报告。

## 必查项目

- 每只人手必须能独立追踪五根手指；四指、六指、双拇指、分叉、融合、悬空指尖都应指出。
- 每只手必须有独立的长度关系检查，考虑弯曲与透视缩短。明显过长的小指、异常短指、拉长指节、跨画面变长等不能跳过。食指与无名指不强制固定长短顺序。
- 检查掌部起点、指节连接、关节弯曲方向、指甲位置、穿插、左右手及跨画面一致性。
- 双手动作检查两只手；多格教学图检查每格。无法分辨的遮挡记为“待复核”，不能假设被挡住的手指是正确的。

## 判定与发布

任何必查项失败即拒绝；存在不确定项即待复核；所有项目都有可见证据支持才通过。每份报告记录图片指纹，换图后必须重新审阅。

图谱构建时，同时要求动作内容审核通过、形态报告通过、图片指纹一致。图片生成成功不等于通过。教学图详情可下载对应报告，并切回原始研究素材。

`check_report.py` 只检查报告结构、结论一致性和图片指纹；真正的手形判断由能查看图像的 agent 完成。静态图审阅不证明连续运动、隐藏骨骼或物理可行性，也没有经过足以保证零漏检的大规模准确率评测。

## 已运行的检查

使用实际图片独立审阅了正常五指示例、四指且跨格左右手改变的失败示例，以及专门制作的小指异常过长样例。后两个被拒绝，正常示例通过。测试样例仅存于开发目录，不作为动作图展示。

另有发布规则回归检查，覆盖换图沿用旧报告、把拒绝改成通过、遗漏手指或长度检查、遮挡未解仍放行及遗漏画面。这些检查验证发布规则，不代替像素层面的手形判断。
